# DATA_MANIFEST — external data inputs

**Scope.** Everything under `data/` (67.97 GB, 2,873 files as of 2026-07-03) is
deliberately **not tracked in git** (`.gitignore` § Data): raw ministry files and
licensed rasters live on IDB servers / OneDrive. This manifest is the contract that
makes the repo reproducible anyway: it records what must be placed where, from which
source, at which version, before running the pipeline.

Sizes and file counts below were measured on the working copy on **2026-07-03**
(`Get-ChildItem -Recurse -Force`). Where an upstream version is not pinned by the
file name itself, the "Version / provenance" column says how the version can (or
cannot) be recovered — open gaps are tracked in §6.

## 2. School registries (`data/schools/`)

- **Layout.** `data/schools/AR/{ISO}/raw/` (8.37 GB, 329 files) and
  `data/schools/AR/{ISO}/processed/` (0.75 GB, 109 files); the remainder is
  per-country caches (e.g. BRA `schools_2023.gpkg`, ~101 MB) and legacy LAC merges.
- **Source.** One ministry/EMIS export per country, collected by the project.
  Per-country source notes live in `docs/pipeline_history.md`,
  `docs/coordinate_quality_spec.md` §7, and each `{ISO}_script.qmd` in the bundle.
- **Version.** Raw files are frozen as received (they are the primary input, not
  re-downloadable at a pinned URL). The processed CIMA files
  (`{ISO}_total_cima.csv`, 47 columns) are regenerated from raw by Steps 01–02.
- **Redistribution.** Raw ministry data is **not** redistributed via git or the
  delivery repo — it ships as a data bundle on IDB storage.
- **Special case BRA.** `01_build_cima.py` auto-downloads the INEP `schools_2023.gpkg`
  cache from IPEA/geobr (pinned release v1.7.0 as fallback URL) if absent.

## 3. Population (`data/population/`)

- **WorldPop 100 m, country-level:** `WorldPop/{ISO}/{iso}_pop_2023_CN_100m_R2025A_v1.tif`
  — version pinned by filename (2023 constrained, release R2025A v1, **not**
  UN-adjusted; decision documented in `docs/validation_pop_grid_2026-05.md`).
- **WorldPop 1 km age/sex, LAC-clipped:**
  `WorldPop/LAC/clipped_global_{f,m}_{05,10,15}_2023_CN_1km_R2025A_UA_v1.tif`
  (6 rasters) — pinned by filename.
- **Derived grid:** `WorldPop/processed/population_grid_{ISO}.csv` +
  `_manifest.csv` (per-country summary) — regenerated by Step 06.
- **Source:** https://www.worldpop.org (manual download; Step 06 does **not**
  download, it expects the rasters in place).
- **Known gap:** HTI has no WorldPop raster (only country without a grid).

## 4. Transportation (`data/transportation/`)

- **`surface_friction/` (4.51 GB, 91 files).** Malaria Atlas Project global
  friction surfaces, pinned by filename:
  `202001_Global_Motorized_Friction_Surface_2019`,
  `202001_Global_Walking_Only_Friction_Surface_2019`,
  `201501_Global_Travel_Speed_Friction_Surface_2015` (+ per-country clips from
  Step 07 friction clip). Source: https://malariaatlas.org (Weiss et al. 2020).
- **`travel_times/` (4.07 GB, 348 files).** FMM travel-time rasters emitted by
  Step 09 (2 modes × 3 levels × sectors per country) — fully regenerable.
- **`osrm/` (29.49 GB, 1,083 files).** OSRM MLD graphs per country built by
  `09b_osrm_build_and_run.sh` from Geofabrik extracts
  (`download.geofabrik.de/{region}/{country}-latest.osm.pbf`; BHS/BRB from
  `download.openstreetmap.fr`). **Provenance caveat:** see §6.

## 5. Boundaries, poverty, wealth

- **`data/bounderys/LAC/`**: BID admin polygons level 1 and level 2 (12,531 ADM2)
  — the authoritative geographic frame; received from BID, not publicly pinned.
  Country aux shapefiles (e.g. DOM `RD_MUNICIPIOS`) sit alongside.
- **`data/Poverty Rates/lac-level-{1,2}.csv`**: IDB subnational poverty/NBI rates.
- **`data/Poverty Rates/meta-rwi/`**: Meta Relative Wealth Index rasters
  (~2.4 km; source: Data for Good at Meta via HDX).

## 6. Known provenance gaps (open items from `docs/pipeline_data_audit_2026-05-27.md`)

1. **OSM extract dates are not pinned (PROV-2, open).** The 09b driver downloads
   `-latest.osm.pbf`; the production run used extracts dated between
   2026-05-17 and 2026-05-22 (recoverable only from `osrm-extract` timestamps in
   the run logs, inventoried in the audit doc §1.1). The cached `.pbf` files were
   not preserved. Any OSRM re-run is a *new* OSM snapshot, not a replication.
2. **OSRM Docker image untagged (PROV-2, open).** `09b_osrm_build_and_run.sh` uses
   `osrm/osrm-backend` (implicit `latest`).
3. **No per-run consolidated manifest (PROV-3, open).** This file documents the
   *inputs*; a machine-readable per-run manifest (input digests + `data_year`)
   is still pending.
4. **Geocoding (Step 04) is inherently non-replayable**: ArcGIS/Photon/Nominatim
   are live services. The outcomes of record are already materialized in each
   `{ISO}_total_cima.csv` and the append-only ledger `results/geocode_results.csv`
   (shipped in the data bundle) — Step 04 is only re-run for new countries, never
   to reproduce old results.

## 7. Reproducing a run

1. Clone the repo; install uv. `uv sync` restores the exact Python environment
   (`uv.lock` + `.python-version` are tracked).
2. Obtain the data bundle from IDB storage and place it at `data/` (or point
   `IDB_ACCESS_DATA_ROOT` / `IDB_ACCESS_RESULTS_ROOT` elsewhere — see
   `pipeline/_paths.py`).
3. `uv run python pipeline/run_all.py` (Steps 01–03), then the on-demand steps in
   numeric order (see README § Running the Pipeline).
4. Checksums: no per-file digest list is maintained yet (PROV-3). To fingerprint
   a bundle before hand-off:
   `Get-ChildItem data -Recurse -File | Get-FileHash -Algorithm SHA256 > data_sha256.txt`
   (PowerShell) or `find data -type f -exec sha256sum {} + > data_sha256.txt` (bash).
